# Oracle schema contract

## OTP_EMAIL_LOCKS

`email VARCHAR2(320 CHAR) PRIMARY KEY`, `resend_after TIMESTAMP WITH TIME ZONE NULL`, `created_at TIMESTAMP WITH TIME ZONE DEFAULT SYSTIMESTAMP NOT NULL`. Authentication locks the row per email using SELECT FOR UPDATE before reserving an OTP dispatch window. This serializes sign-in and registration code delivery across concurrent API requests using Oracle only.

This document is the backend SQL interface. Names are uppercase in Oracle and the Node database adapter returns lowercase keys. All timestamps are `TIMESTAMP WITH TIME ZONE`; IDs in the ten ER entities and `DEPARTMENTS` are `NUMBER` identity values generated by Oracle. `OTP_CHALLENGES`, `SESSIONS`, and `UPLOADS` use application-generated random string IDs. Seed rows are synthetic demonstration data; `@campus.test` addresses are seed identities only and require a configured reachable address for real email delivery. No real Aadhaar data is seeded.

## API mapping notes

- `User.student_id` comes from STUDENTS.id; `company_id` and `department_id` come from USERS.
- Student full name and email come from USERS; phone numbers from STUDENT_PHONE_NUMBERS; skills from `skills_json`.
- Opportunity lists expose normalized skills/departments as arrays, or their JSON mirrors; `eligible_department_ids` are IDs from OPPORTUNITY_ELIGIBLE_DEPARTMENTS.
- Application records join STUDENTS, USERS, OPPORTUNITIES, and COMPANIES for names and type.
- Outcome records join via APPLICATIONS for student/company/opportunity context.
- The seed-only sign-in addresses are `admin@campus.test`, `recruiter@campus.test`, and `student@campus.test`; they are not reachable mailboxes.

- HACKATHONS.event_mode maps to API `mode`; MODE is reserved in the installed Oracle version.
